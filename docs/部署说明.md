# DSH Move 管理后台 · 部署说明

## 一、项目概览

- 技术栈：Vue 3 + TypeScript + Vite + Element Plus + ECharts + Pinia
- 部署方式：GitHub Pages 静态托管（仅前端静态资源，无服务端渲染）
- 数据来源：默认 Mock 引擎；生产环境通过 `VITE_API_BASE` 指向独立后端接口
- 路由：hash 路由（`#/xxx`），静态托管下无需服务端 rewrite 即可刷新/直达

## 二、本地调试启动命令

```bash
# 1. 安装依赖
npm install

# 2. 本地开发（默认 http://localhost:5173）
npm run dev

# 3. 类型检查
npm run typecheck

# 4. 代码规范检查
npm run lint

# 5. 生产构建（产物输出到 dist/）
npm run build

# 6. 本地预览构建产物
npm run preview
```

本地调试如需切换到真实后端，创建 `.env.local`：

```bash
VITE_API_BASE=https://your-backend.example.com
```

## 三、环境变量配置清单

| 变量 | 说明 | 默认值 | 注入方式 |
| --- | --- | --- | --- |
| `VITE_API_BASE` | 后端 API 基础地址；`/mock` 走内置 Mock 引擎 | `/mock` | GitHub Secrets |
| `VITE_BASE_PATH` | 站点部署子路径 | `./` | GitHub Secrets |
| `VITE_SESSION_TIMEOUT` | 会话超时（分钟） | `30` | 可选 |
| `VITE_POLL_INTERVAL` | 看板短轮询降级间隔（毫秒） | `15000` | 可选 |

> ⚠️ 安全约束：所有密钥、凭证一律通过 GitHub Secrets 注入，**禁止**硬编码到前端业务代码或提交到仓库版本记录。

## 四、GitHub Pages 部署步骤

### 1. 创建仓库

在 GitHub 创建仓库 `MRStudioGame/dsh-admin`（公开），推送源码：

```bash
git init
git remote add origin https://github.com/MRStudioGame/dsh-admin.git
git add .
git commit -m "init: DSH Move 管理后台"
git branch -M main
git push -u origin main
```

### 2. 配置 Secrets

仓库 `Settings → Secrets and variables → Actions → New repository secret`，添加：

- `VITE_API_BASE`：`/mock`（接真实后端时改为后端地址）

### 3. 启用 Pages

`Settings → Pages → Build and deployment`：

- **Source**：`GitHub Actions`

### 4. 触发部署

推送 `main` 分支自动触发 `.github/workflows/deploy.yml` 流水线：

1. 安装依赖
2. Lint 校验
3. 类型检查
4. 生产构建
5. 上传 Pages artifact
6. 自动部署

部署完成后访问：`https://mrstudiogame.github.io/dsh-admin/`

### 5. 版本回滚

GitHub Pages 基于 `main` 分支部署，回滚即 `git revert` 目标提交后推送，流水线自动重建部署。

├── .github/workflows/deploy.yml   # CI/CD 流水线

## 七、已知边界（Mock 模式）

1. 数据为内存态，刷新页面后种子数据会重置演化，非持久化；
2. 实时推送为前端定时器模拟，非真实 WebSocket；
3. 接入真实后端后，需后端提供对应的 REST 接口（见 `src/api/index.ts` 的 `realImpl`）与 WebSocket 实时通道。
