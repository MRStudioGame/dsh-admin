# DSH Move 管理后台 · 部署说明

## 一、项目概览

- 技术栈：Vue 3 + TypeScript + Vite + Element Plus + ECharts + Pinia
- 部署方式：GitHub Pages 静态托管（仅前端静态资源，无服务端渲染）
- 数据来源：默认 Mock 引擎；生产环境通过 `VITE_API_BASE` 指向独立后端接口
- 路由：hash 路由（`#/xxx`），静态托管下无需服务端 rewrite 即可刷新/直达

## 二、本地调试启动命令

```bash
# 1. 安装依赖
npm install

# 2. 本地开发（默认 http://localhost:5173）
npm run dev

# 3. 类型检查
npm run typecheck

# 4. 代码规范检查
npm run lint

# 5. 生产构建（产物输出到 dist/）
npm run build

# 6. 本地预览构建产物
npm run preview
```

本地调试如需切换到真实后端，创建 `.env.local`：

```bash
VITE_API_BASE=https://your-backend.example.com
```

## 三、环境变量配置清单

| 变量 | 说明 | 默认值 | 注入方式 |
| --- | --- | --- | --- |
| `VITE_API_BASE` | 后端 API 基础地址；`/mock` 走内置 Mock 引擎 | `/mock` | GitHub Secrets |
| `VITE_BASE_PATH` | 站点部署子路径 | `./` | GitHub Secrets |
| `VITE_SESSION_TIMEOUT` | 会话超时（分钟） | `30` | 可选 |
| `VITE_POLL_INTERVAL` | 看板短轮询降级间隔（毫秒） | `15000` | 可选 |

> ⚠️ 安全约束：所有密钥、凭证一律通过 GitHub Secrets 注入，**禁止**硬编码到前端业务代码或提交到仓库版本记录。

## 四、GitHub Pages 部署步骤

### 1. 创建仓库

在 GitHub 创建仓库 `MRStudioGame/dsh-admin`（公开），推送源码：

```bash
git init
git remote add origin https://github.com/MRStudioGame/dsh-admin.git
git add .
git commit -m "init: DSH Move 管理后台"
git branch -M main
git push -u origin main
```

### 2. 配置 Secrets

仓库 `Settings → Secrets and variables → Actions → New repository secret`，添加：

- `VITE_API_BASE`：`/mock`（接真实后端时改为后端地址）

### 3. 启用 Pages

`Settings → Pages → Build and deployment`：

- **Source**：`GitHub Actions`

### 4. 触发部署

推送 `main` 分支自动触发 `.github/workflows/deploy.yml` 流水线：

1. 安装依赖
2. Lint 校验
3. 类型检查
4. 生产构建
5. 上传 Pages artifact
6. 自动部署

部署完成后访问：`https://mrstudiogame.github.io/dsh-admin/`

### 5. 版本回滚

GitHub Pages 基于 `main` 分支部署，回滚即 `git revert` 目标提交后推送，流水线自动重建部署。

## 七、已知边界（Mock 模式）

1. 数据为内存态，刷新页面后种子数据会重置演化，非持久化；
2. 实时推送为前端定时器模拟，非真实 WebSocket；
3. 接入真实后端后，需后端提供对应的 REST 接口（见 `src/api/index.ts` 的 `realImpl`）与 WebSocket 实时通道。

## 八、客户端 App 内更新接口（v2.5.0）

客户端（DSH Move v2.4.0 起）不再跳转官网下载页，改为请求管理端版本接口；
**v2.5.0 起（合并未单独发布的 v2.4.1 修复）彻底移除官网 `version.json` 兜底清单与官网 `#download` 页面直链**，
本接口成为版本信息的唯一来源。接口失败、APK 直链超时 / 404 / 无法拉取时，
客户端统一提示「更新资源获取失败，请稍后重试」，提供「重新拉取」，
任何更新分支都不跳转官网、不打开浏览器。

```
GET https://mrstudiogame.github.io/dsh-admin/api/app-version.json
```

静态 Pages 部署时，该地址由 `public/api/app-version.json` 原样发布；接入独立后端后，
把 `VITE_API_BASE` 指向后端，接口自动切换为 `GET {VITE_API_BASE}/app-version.json`，
客户端解析逻辑无需改动（见 `src/api/index.ts` 的 `fetchAppRelease`）。

响应字段：

| 字段 | 说明 |
| --- | --- |
| `version` / `build` | 最新版本号与构建号，客户端按语义化版本号 + 构建号双重比对 |
| `notes` / `changelog` | 更新日志（摘要 / 逐条） |
| `apkUrl` / `apkFallbackUrls` | APK 直链与备用通道（加速镜像 → Pages 自托管 → GitHub 原始地址） |
| `md5` | 安装包 MD5，客户端下载完成后强制校验，不通过拒绝安装 |
| `size` | 包大小（字节），用于下载进度与更新弹窗展示 |
| `sha256` | 仅作存档校验，不参与客户端强校验 |
| `force` | 是否强制更新（预留） |

发布新版本流程：上传 APK 到 Releases / Pages → 用 `md5sum` 与文件字节数更新
`public/api/app-version.json` 的 `md5`、`sha256`、`size`、`apkUrl` → 推送 `main`，
Actions 自动重建并部署。页面「系统设置 → 客户端版本发布」会实时展示该清单。

> 清单中不含任何密钥；MD5 只用于完整性校验，不用于鉴权。
>
> v2.5.0 客户端硬性校验：`apkUrl` / `apkFallbackUrls` 必须是以 `.apk` 结尾的
> http(s) 文件直链（网页地址会被拒收），`md5` 必须为 32 位十六进制；
> 任一不满足即判定「更新资源获取失败」，不会回落到官网页面。
